# 상태 관리

## 상태(State)란 무엇인가

상태는 **앱의 동작 중에 변할 수 있는 데이터**를 의미한다.

사용자 입력, 네트워크 응답, 시간 경과 등에 따라 앱의 UI가 변경되어야 할 때 이러한 변경사항을 관리하는 데이터를 상태라고 한다.

---

# 1. 임시 상태 (Ephemeral State)

- 단일 위젯 내에서만 사용되는 간단한 상태
- UI의 일시적인 변화를 관리
- 예시
  - 버튼 눌림 상태
  - 입력 필드 포커스
- `StatefulWidget`과 `setState()`로 쉽게 관리할 수 있다.

---

# 2. 앱 상태 (App State)

- 앱의 여러 부분에서 공유되는 데이터
- 장기적으로 유지되어야 하는 정보
- 예시
  - 사용자 설정
  - 인증 토큰
  - 쇼핑 카트 내용
- 전역적으로 접근 가능해야 하며 효율적인 관리가 필요하다.
- 상태 관리 라이브러리를 활용하여 관리할 수 있다.
  - `Provider`
  - `Riverpod`
  - `Bloc` 등

---

# 3. 상태 관리가 중요한 이유

## ① UI 일관성

- 상태 변화에 따라 UI가 일관되게 업데이트되어야 한다.

## ② 코드 구조화

- 앱의 상태 로직과 UI 로직을 분리하여 유지보수성을 향상시킬 수 있다.

## ③ 성능 최적화

- 필요한 부분만 효율적으로 다시 빌드하여 성능을 개선할 수 있다.

## ④ 확장성

- 앱의 규모가 커져도 상태를 효과적으로 관리할 수 있는 구조가 필요하다.

---

# 4. 상태 관리 방식의 진화

## ① `StatefulWidget`과 `setState()`

Flutter의 기본적인 상태 관리 메커니즘이다.

간단한 상태를 위젯 내부에서 관리한다.

### 장점

- 간단하고 직관적이다.

### 단점

- 깊은 위젯 트리에서 상태 전달이 어렵다.
- `Prop drilling` 문제가 발생할 수 있다.

---

## ② `InheritedWidget`

Flutter의 내장 메커니즘이다.

위젯 트리 아래로 데이터를 효율적으로 전달한다.

### 장점

- 위젯 트리를 통한 데이터 전파

### 단점

- 직접 구현하기 복잡하다.

---

## ③ Provider 패턴

`InheritedWidget`을 래핑한 패키지이다.

더 사용하기 쉬운 API를 제공한다.

### 장점

- 사용하기 쉽고 직관적이다.

### 단점

- 복잡한 상태 관리에는 한계가 있다.

---

## ④ 현대적 상태 관리 솔루션

현재는 다양한 상태 관리 라이브러리가 존재한다.

### Riverpod

- `Provider`의 개선 버전
- 컴파일 타임 안전성 및 테스트 용이성을 강화

### Bloc / Cubit

- 비즈니스 로직을 명확하게 분리하는 패턴

### MobX

- 반응형 프로그래밍 기반의 상태 관리

### Redux

- 예측 가능한 상태 컨테이너

---

# 5. 상태 관리 선택 가이드

## ① 앱 복잡도

- 단순한 앱의 경우 `setState()`나 `Provider`로도 충분할 수 있다.

## ② 팀 경험

- 팀이 이미 익숙한 솔루션이 있다면 고려한다.

## ③ 학습 곡선

- 일부 솔루션은 배우기 어려울 수 있다.

## ④ 성능 요구사항

- 대규모 앱의 경우 성능 최적화된 솔루션이 필요할 수 있다.

## ⑤ 테스트 용이성

- 상태 로직의 테스트 용이성도 중요한 고려사항이다.
