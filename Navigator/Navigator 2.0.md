# Navigator 2.0

- Flutter 1.22 버전에서 도입된 `Navigator 2.0`은 이전의 명령형 스타일인 `Navigator 1.0`을 보완하는 선언적 접근 방식의 네비게이션 API이다.
- 복잡한 라우팅 시나리오와 웹 애플리케이션의 딥 링크 처리를 더 효과적으로 관리할 수 있도록 설계되었다.

---

# 1. Navigator 2.0의 등장 배경

### ① 앱 상태와 URL 동기화 어려움
- 웹에서 URL을 기반으로 화면을 관리하기 어려웠다.

### ② 딥 링크 처리의 복잡성
- 특정 화면으로 직접 이동하는 딥 링크 구현이 복잡했다.

### ③ 선언적 UI와의 불일치
- Flutter의 나머지 부분은 선언적인 방식인데 네비게이션만 명령형 방식이었다.

### ④ 전체 라우팅 상태 관리 부재
- 앱의 전체 네비게이션 상태를 한 곳에서 관리하기 어려웠다.

---

# 2. Navigator 2.0의 핵심 컴포넌트

## ① Router

- `Navigator 2.0`의 최상위 위젯이다.
- 라우팅 정보를 처리하고 적절한 화면을 표시한다.
- 주로 `MaterialApp.router` 생성자를 통해 사용한다.

---

## ② RouteInformationParser

- URL 경로와 같은 라우트 정보를 앱의 상태 객체로 변환하는 역할을 한다.
- 예를 들어 `/users/123`과 같은 URL을 `UserDetailsState(userId: 123)`과 같은 앱 상태 객체로 변환할 수 있다.

---

## ③ RouterDelegate

- 앱의 상태를 기반으로 `Navigator` 위젯과 그 안의 페이지 스택을 구성한다.
- 앱의 상태가 변경되면 이를 감지하고 화면을 업데이트한다.

---

# 3. Navigator 2.0의 핵심 개념

## ① Page 위젯

- `Navigator 2.0`에서는 화면을 `Page` 위젯으로 표현한다.
- `Page`는 화면에 표시될 내용과 전환 애니메이션을 정의하는 불변 객체이다.

### 주요 Page 구현체

- `MaterialPage`
  - Material Design 스타일의 화면 전환

- `CupertinoPage`
  - iOS 스타일의 화면 전환

- `CustomPage`
  - 커스텀 애니메이션을 정의한 화면 전환

---

## ② 선언적 방식의 페이지 스택 관리

- `Navigator 2.0`의 가장 큰 특징은 페이지 스택을 선언적으로 관리한다는 점이다.
- 화면 추가와 제거를 명령형 메서드인 `push`, `pop`으로 처리하는 대신 전체 페이지 스택을 한 번에 정의한다.

### 선언적 방식의 장점

- 앱의 상태와 UI가 항상 동기화된다.
- 라우팅 상태가 변경되면 전체 페이지 스택이 자동으로 업데이트된다.

---

## ③ 히스토리 스택 관리

- `Navigator 2.0`은 브라우저의 히스토리 스택과 통합할 수 있다.
- 사용자가 브라우저의 뒤로 가기 또는 앞으로 가기 버튼을 사용할 때 앱의 상태가 적절히 변경되도록 할 수 있다.

---

# 4. Navigator 2.0의 장단점

## 장점

### ① 선언적 API
- 앱의 상태와 UI가 항상 동기화된다.

### ② 딥 링크 지원 개선
- 복잡한 딥 링크 시나리오를 더 쉽게 처리할 수 있다.

### ③ 웹 통합
- 브라우저 히스토리와 URL을 앱 상태와 동기화할 수 있다.

### ④ 상태 기반 라우팅
- 전체 앱 상태를 기반으로 라우팅을 관리할 수 있다.

### ⑤ 테스트 용이성
- 선언적 API는 테스트하기 더 쉽다.

---

## 단점

### ① 복잡성
- `Navigator 1.0`보다 구현이 더 복잡하다.

### ② 코드량 증가
- 간단한 앱에서는 오히려 코드가 더 복잡해질 수 있다.

### ③ 라이브러리 성숙도
- 관련 생태계가 `Navigator 1.0`만큼 성숙하지 않았다.

---

# 5. Navigator 2.0 사용 시 고려사항

## 언제 Navigator 2.0을 사용하는가

### ① 웹 지원 필요
- Flutter 웹 앱에서 URL 관리가 중요한 경우

### ② 복잡한 딥 링크
- 다양한 딥 링크 시나리오를 처리해야 하는 경우

### ③ 상태 기반 라우팅
- 앱 상태와 라우팅이 밀접하게 연결된 경우

### ④ 중첩 네비게이션
- 복잡한 중첩 네비게이션 구조가 필요한 경우

---

# 6. go_router

- `Navigator 2.0`의 복잡성을 줄이기 위한 라우팅 패키지이다.
- `Navigator 2.0`의 기능을 활용하면서도 더 간단한 API를 제공한다.
